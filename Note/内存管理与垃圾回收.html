V8内存管理与垃圾回收（GC）

V8的堆内存主要分为新生代(New Space)和老生代(Old Space)。

  1. 新生代（New Space）- 存活时间短的对象

    • 场景：函数内部的临时变量，用完即弃。新创建的对象（有一个例外，非常大的对象可能会直接进入老生代）
    • 大小：通常较小（在64位系统上，默认约16MB到32MB）。可以通过V8的 --max-semi-space-size 和 --min-semi-space-size 标志调整。
    • 算法：Scavenge(清除算法)（一种“复制”算法）
    • 特点：
      • 绝大多数对象在这里诞生并很快死去
      • 回收非常频繁，速度极快
      • 空间被分为两个相等的半空间（Semi-space）：Form空间（使用中）和To空间（闲置）
    • 原理：将空间一分为二：From空间和To空间。
      1. 新对象分配在From。
      2. GC开始时，检查From里的存活对象，复制到To。
      3. 清空From。
      4. From和To角色互换。
    • 特点：牺牲空间换时间（总有一半空间闲置），但因为存活对象少，复制成本极低，速度极快，只处理存活对象，且复制过程自然完成了内存整理，没有碎片

  2. 老生代（Old Space）- 常驻内存的对象

    • 场景：全局对象、闭包引用的变量、经历过多次（经历过至少一次，通常为两次）Scavenge依然存活的对象（晋升）、一些大对象可能会被直接分配到这里。
    • 大小：远大于新生代，主堆的主要部分（在64位系统上可达数百MB甚至超过1GB，具体取决于可用内存）。可以通过 --max-old-space-size 调整。
    • 算法：标记-清除（Mark-Sweep）& 标记-整理（Mark-Compact）
      1. 标记：遍历所有对象，标记活着的对象。
      2. 清除：清除没被标记的垃圾。（会产生内存碎片）
      3. 整理：(为了解决内存碎片)将活着的对象往内存一端移动，连续排列。
    • 特点：
      • 对象存活率高，回收不如新生代频繁。
      • 空间大，回收速度比新生代慢得多，但处理的频率也低。
    • 优化：为了避免GC时全停顿（Stop-The-World），V8使用了增量标记（Incremental Marking），即把标记过程拆分成小任务，穿插在JS执行间隙进行。

  3. 常见的内存泄漏场景

    • 意外的全局变量：忘记写let/const
    • 被遗忘的定时器：setInterval没有clearInterval
    • 闭包：函数返回了一个内部函数，导致外部函数的变量无法被回收
    • DOM引用：JS中保留了DOM节点的引用，即使从页面移除该节点，它依然占用内存

  4. 工作流程与晋升
    一个新对象 {} 的生命周期通常如下：

    1. 在新生代的From空间被分配。
    2. 当新生代需要进行GC（空间将满时）时，V8会启动一次 Minor GC（副垃圾回收），使用Scavenge算法。
    3. 如果这个对象在这次GC中存活，它会被复制到To空间。From和To空间交换。
    4. 如果这个对象在新生代中经历了几轮GC（通常是1到2次）后仍然存活，它会被认为是“老”对象，从新生代晋升到老生代。
    5. 当老生代的空间占用达到一定阈值时，V8会启动一次 Major GC（主垃圾回收），使用标记-清除/整理算法来清理整个老生代（有时也包括大对象空间、代码空间等）。这个过程也称为 Full GC，可能会引起明显的停顿。

  5. 其它重要的堆空间

    • 大对象空间 (Large Object Space)：存放体积非常大的对象（例如巨大的数组或字符串）。这类对象不会在新生代中分配，而是直接在这里创建，也不会被Scavenge算法移动。由老生代的GC管理。
    • 代码空间 (Code Space)：专门存放经过即时编译（JIT）后生成的机器代码。这是可执行内存。
    • Map空间 (Map Space)：专门存放对象的隐藏类（Hidden Class 或 Map）。隐藏类是V8实现快速属性访问的关键数据结构，将它们集中存放有利于管理和回收。

  6. 内存碎片

    1. 外部碎片

      最常见的碎片类型，发生在已分配内存块之间

      工作原理：

      • 内存中已经分配了多个不同大小的块

      • 这些块之间形成了许多小空隙

      • 虽然这些空隙的总和可能很大，但每个单独的空隙都太小，无法满足新的内存分配请求

        内存布局：[已分配10KB][空闲5KB][已分配20KB][空闲3KB][已分配15KB]

    2. 内存碎片

      发生在已分配内存块内部的浪费空间

      工作原理：

      • 内存分配器通常按固定大小的"页"或"块"进行分配

      • 如果请求的内存小于分配单元的大小，剩余部分就被浪费在块内

        示例：

        • 内存分配的最小单位是8字节
        • 程序只请求5字节
        • 系统仍然分配8字节，其中3字节被浪费（内部碎片）

    3. 碎片的影响

      1. 内存浪费：大量内存因碎片化而无法使用
      2. 分配失败：即使总内存足够，分配仍可能失败
      3. 性能下降：分配器需要花费更多时间寻找合适空间
      4. 触发频繁GC：内存不足错觉导致不必要的垃圾回收

    4. 解决内存碎片的方法

      1. 内存整理

        V8的标记-整理算法就是解决方案：

        // 整理前（有碎片）：
[对象A:10KB][空闲:20KB][对象C:15KB][空闲:8KB]

// 整理过程：
// 1. 将所有存活对象向一端移动
[对象A:10KB][对象C:15KB][空闲:28KB]

// 2. 空闲内存合并为一个大块

        优点：完全消除外部碎片
        缺点：需要移动对象，成本较高

      2. 分代垃圾回收

        • 新生代使用Scavenge算法：复制方式天然避免碎片
        • 老生代使用标记-清除/整理组合：权衡碎片和性能

      3. V8的优化策略

        1. 晋升阈值调整：对象在新生代停留更久，减少过早晋升到老生代
        2. 增量标记整理：将完整的整理过程分成多个小步骤，减少停顿
        3. 并行/并发整理：利用多线程减少对主线程的影响
